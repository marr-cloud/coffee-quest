# cloudflare-workers-template

A production-minded starter template for [Cloudflare Workers](https://developers.cloudflare.com/workers/):
TypeScript, Vitest running inside `workerd`, oxlint, Prettier and CI — wired up and green from the first clone.

## Use this template

Click **Use this template** on GitHub, or:

```sh
npx degit marr-cloud/cloudflare-workers-template my-worker
cd my-worker
pnpm install
```

Then rename the project in two places:

| File             | Field  |
| ---------------- | ------ |
| `package.json`   | `name` |
| `wrangler.jsonc` | `name` |

## Requirements

- Node.js — the version in [`.node-version`](.node-version) (minimum `>=22.12.0`)
- pnpm — the version pinned by `packageManager` in [`package.json`](package.json); `corepack enable` picks it up automatically
- A [Cloudflare account](https://dash.cloudflare.com/sign-up) to deploy

## Quick start

```sh
pnpm install
pnpm dev      # http://localhost:8787
pnpm check    # lint + format + typecheck + test
```

## Scripts

| Script              | What it does                                         |
| ------------------- | ---------------------------------------------------- |
| `pnpm dev`          | Local dev server via `wrangler dev`                  |
| `pnpm test`         | Run the suite once (used by CI)                      |
| `pnpm test:watch`   | Run the suite in watch mode                          |
| `pnpm typecheck`    | `tsc --noEmit` over `src/` **and** `test/`           |
| `pnpm lint`         | oxlint (`correctness` + `suspicious` as errors)      |
| `pnpm lint:fix`     | oxlint with autofix                                  |
| `pnpm format`       | Prettier write                                       |
| `pnpm format:check` | Prettier check (used by CI)                          |
| `pnpm check`        | All four gates, in the same order CI runs them       |
| `pnpm cf-typegen`   | Regenerate `worker-configuration.d.ts` from bindings |
| `pnpm deploy`       | `wrangler deploy`                                    |

## Project structure

```sh
src/index.ts              Worker entry point (fetch handler)
test/index.spec.ts        Tests, executed inside workerd via @cloudflare/vitest-plugin
wrangler.jsonc            Worker config: bindings, vars, compatibility, observability
worker-configuration.d.ts GENERATED by `pnpm cf-typegen` — never edit or format by hand
.github/workflows/        CI (every push/PR) and deploy (manual)
```

## Adding a binding

Bindings are the in-process handle to KV, R2, D1, Queues and the rest — always prefer them
over calling the Cloudflare REST API from inside a Worker.

1. Add the binding to [`wrangler.jsonc`](wrangler.jsonc) (commented examples are in the file).
2. Run `pnpm cf-typegen`.
3. Use it as `env.MY_BINDING` — fully typed, no hand-written `Env` interface.

`worker-configuration.d.ts` is generated output. It is listed in
[`.prettierignore`](.prettierignore) on purpose: formatting it produces thousands of lines
of spurious diff on the next regeneration.

## Environment variables and secrets

Non-sensitive values go in `vars` in `wrangler.jsonc` and are committed.

Secrets never go in `wrangler.jsonc` or in source:

```sh
# Local development: copy the example and fill it in (.dev.vars is gitignored)
cp .dev.vars.example .dev.vars

# Production
npx wrangler secret put MY_API_KEY
```

## Deploying

```sh
npx wrangler login
pnpm deploy
```

For CI deploys, set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as secrets on the
`production` environment, then run the **Deploy** workflow. It is `workflow_dispatch`-only by
default; uncomment the `push` trigger in
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) to deploy on every merge to `main`.

## Conventions

- **Formatting** — Prettier, tabs, 140 columns ([`.prettierrc`](.prettierrc)), with
  [`.editorconfig`](.editorconfig) keeping non-Prettier editors in line.
- **Linting** — oxlint with `correctness` and `suspicious` promoted to errors.
- **Types** — `strict`, plus `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`
  and `verbatimModuleSyntax`.
- **Compatibility date** — bump `compatibility_date` in `wrangler.jsonc` deliberately, and
  re-run `pnpm cf-typegen` afterwards.
- **Dependencies** — Dependabot opens weekly grouped PRs.
